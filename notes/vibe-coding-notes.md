《通用版 Vibe Coding 工程约束》
## 【通用 Vibe Coding 协作与外部记忆工程约束】
为防止长对话导致的上下文污染、记忆丢失与代码幻觉，在本次项目开发中，你必须严格执行以下 4 项工程规范：

1. **Windows CMD 自动化脚手架：** 
   在初始化项目或新增模块时，请直接提供兼容 **Windows CMD** 的命令行脚本（使用 `mkdir` 建立文件夹，使用 `type nul >` 创建空文件），协助我一键在本地生成目录结构与基础文件，严禁混用 Linux 专属命令（如 `touch`、`mkdir -p`）。
2. **外部记忆库 (`./doc/` 目录)：** 
   项目根目录下必须建立 `doc` 文件夹，作为你的“外部持久记忆体”以减轻上下文检索负担：
   - `doc/blueprint.md`：记录项目的全局架构图、模块划分与不可篡改的接口契约。
   - `doc/dev-memory.md`：作为内部开发版本库与状态快照。
3. **内部版本演进与“记忆胶囊”机制：**
   当我们完成基础架构或任意一个独立功能模块并通过我的测试后，你必须主动命名并升级一个内部版本号（格式如：`v0.1.0-chassis`、`v0.2.0-moduleA`）。每次版本升级时，请输出更新后的 `doc/dev-memory.md` 内容，浓缩记录：
   - 【当前版本号与阶段名称】
   - 【已竣工并锁死的文件列表（严禁后续随意修改）】
   - 【各模块暴露的核心接口摘要】
   - 【下一阶段待开发目标】
   这将作为你后续开发的唯一正确记忆基准，避免幻觉。
4. **Git 时光机与 GitHub 同步指令：**
   每当一个内部版本验证通过，请同步为我生成对应的 Windows CMD `git add`、`git commit -m "[版本号] 阶段说明"` 以及同步到 GitHub 远程仓库的命令行指令，确保每一个稳定阶段都有可随时回滚的代码锚点。
